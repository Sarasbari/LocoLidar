# Metric methodology for the public prototype

The deployed prototype must display only values from `evidence/current/metrics.json`.
Every value carries a status: `recomputed`, `not_available`, or `target_only`.

## Recomputed now

`adaptive_cell_reduction_vs_uniform_fine_percent` compares the adaptive map's
occupied 2.5D cell count with occupied XY cells from a fixed 0.25 m grid over
the same input points within a 60 m radial range. It is a spatial aggregation
metric. It is **not** a claim about memory use.

`mapping_only_latency_ms` measures only the call to `Adaptive2_5DConverter`.
It excludes LiDAR loading, semantic inference, rendering, browser work, and
network transfer. It must never be labelled as FPS, model latency, or end-to-end
latency.

The frame-processing result means each cached prediction file passed schema,
finite-coordinate, and map-conversion validation during the recorded run.

## Not shown as achieved until evidence exists

- Semantic validation accuracy requires a held-out ground-truth label set,
  evaluation script, scene-disjoint split manifest, checkpoint identifier, and
  reproducible command.
- Sparse/dense voxel memory reduction requires the baseline implementation,
  grid extent, voxel size, dtype, sparse storage format, and byte-count method.
- End-to-end inference latency requires a trained checkpoint, a documented
  machine/GPU, warm-up policy, frame count, and timing command.
- Any real-time target, including 46 FPS or <22 ms, remains `target_only` until
  it is benchmarked by the same evidence pipeline.

## Provenance labels in the web UI

- **Recomputed**: generated by the checked-in verifier from the current files.
- **Recorded replay**: precomputed LiDAR data shown in the browser; no cloud
  model inference runs when a reviewer opens the link.
- **Deterministic simulation**: a scripted safety/hazard scenario used to
  demonstrate UX behavior, not an observed traffic event.
- **Target only**: design objective, not achieved evidence.
